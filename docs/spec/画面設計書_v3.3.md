Version 3.3 （ 2026年9月11日 ） 対象: iOS・Android ネイティブアプリ

## 1. 設計方針

### 1.1 UI コンセプト

「地図を触る」。DIGGR の主画面はリストではなくカードでもない、手で触れる音楽の意味である。UI は情報を運ぶ器に徹し、視覚の主役は常にグラフに置く。ボタン・ラベル・文字は影と背景に沈み込み、ノードとエッジが浮かび上がる。

### 1.2 設計原則

| 原則 | 具体的な意味 |
| --- | --- |
| 3タップで発見 | 起動 → 検索 → グラフ表示までに余計な画面を挟まない |
| 常時操作 | 主要操作は画面下 1/3（親指到達域）に配置する |
| 常設マーク | グラフの発光表現が成立するためにはマークを既定とし、フライトモードは設定で任意提供 |
| 中断からの復帰 | モーダルによる全画面遮断を避け、シートで文脈を保つ |
| 課題は読める・見える | フォールバックを割り込ませず、未解放領域を見せて読めない状態で示して自然に触らせる |

### 1.3 リファレンスとの差異

先行事例の Every Noise at Once は、網羅性と情報密度を最優先した二次元グリッドである。DIGGR はその情報量をモバイルで扱うため、**一度に見える範囲を1シード＋最大 100 件に限定し、深さは狭いディグの反復で稼ぐ**設計に置き換えた。

ただし v2.0 でジャンル階層を自動で持つことになったため、ジャンルパネル（SC-07）はフラットな一覧ではなく、ツリー構造になり、リファレンスのジャンルの地図を踏襲した意匠に一歩近づいた。全体の俯瞰ビューは v1.1 のジャンルモードとは別機能として別途検討する。

- 基本単位 4pt。余白は 8 / 12 / 16 / 24 / 32 を使う

### 4.4 アニメーション

| トークン | 時間 | 用途 |
| --- | --- | --- |
| `reveal` | **220ms / stagger 20ms** | ノードの出現（FR-28 の段階表示） |
| **`edgeGrow`** | **420ms / ease-out** | **ルートが伸びる**。ノード出現に合わせてエッジが中心側から伸ばす |
| **`breathe.normal`** | **1,500ms / ease-in-out ループ** | **通常状態の呼吸**。地図全体をゆっくり抱かせる |
| **`breathe.marked`** | **380ms / ease-in-out ループ** | **組み込み対象の強調**（SC-16）。通常の 4 倍速 |
| `redig` | 700ms / spring | 掘り直し。選択ノードを中心へ移動させ周囲を再構成する |
| `sheet` | 280ms / ease-out | ボトムシートが背景を 0.6 まで縮小 |
| `select` | 180ms / ease-out | ノード選択拡大 1.0→1.25、発光リング付与 |
| `unlock` | 900ms / ease-in-out | 未解放の実体化（購入完了時） |
| `recenter` | 520ms / ease-out | 「中心に戻る」**カメラとラベルが同じイージングで動く** |

**呼吸（`breathe`）は v3.0 で意味を拡張した**。当初は組み込み対象を強調するためだけの表現だったが、実機で見ると **停止した地図は死んで見える** ことが分かった。

そこで呼吸を 2 速度持たせた――**通常は 1,500ms でぼんやり、組み込み中の対象は 380ms で急ぐ**。同じ表現の速度を変えるだけなので、学習コストをかけずに、遅い呼吸に沈んでいる地図の中で、選ばれたものだけ意識を強くしているという読み方になる。

**設定の「アニメーションを軽減」ですべて停止する**（SC-12）。呼吸は静止リングに、ルートの伸長は即時描画に、段階表示の stagger は一括出現に置き換わる。**OS の「視覚効果を減らす」設定を初期値として読み取る**。

| `ServiceLauncher` | 外部音楽アプリへの遷移ボタン群（FR-23）。4サービス**ID があればディープリンク、なければ検索 URL** |
| `StepRevealButton` | 段階表示ボタン（FR-28）。残件数と状態に応じて 3 つの見た目を持つ |

| `RerollButton` | 引き直し（FR-27）。`meta.canReroll` が false のときは自動で無効化 |
| `AdBanner` | AdMob バナー。Pro ユーザーには描画自体を行わない |
| `EmptyState` | 空状態・エラー状態の展開表示 |
| `Credits` | データ提供元のクレジット。設定画面に配置 |

**v3.0 で削除したコンポーネント**: `PreviewBlock`（プレイヤー）ストアリンクのコンテナ）と `TierBoundary`（境界リング）。共有専用の 2 つ（`HighlightBadge` / `SharedMapBanner`）は v2.4 で削除済み。

**新設したのは `GraphLabels` / `TopChrome` / `RandomToggle` の 3 つ**。このうち 2 つは実機検証由来――ラベルが読めない、タイトルが地図に食われるという報告から生まれている。

**`GraphLabels` を Skia から切り離したのは大きな判断である**。Skia でテキストを描くにはフォントファイルをアセットとして同梱する必要がある。**日本語を含むアーティスト名を扱う以上、フォントサイズが現実的でない**。RN の `<Text>` なら OS のフォントが使える、Dynamic Type と VoiceOver がそのまま効く。

代償は、**ノード（GPU）とラベル（RN ツリー）で描画経路が分かれる**ことである。ジェスチャ中に両者がずれないよう、ラベルには置き直し値から小さい差分変換だけかける（§4.7）。

### 4.6 ボタン

ボタンは画面上で唯一「押されること」を主張している要素である。グラフが静かなぶん、ボタンは明確に立たせる。

#### 4.6.1 形と質感

| 属性 | 値 |
| --- | --- |
| 高さ | Large 52pt、Medium 44pt、Small 36pt |
| 角丸 | **高さの 1/2（完全なピル形）**。カード（16pt）や入力本（12pt）と明確に区別する |
| 横パディング | 高さ × 0.45（Large なら 24pt） |
| ラベル | Label 16 / Semibold、**字間 +0.2pt** |
| アイコン | ラベル左に 20pt、ラベルとの間隔 8pt |
| 影 | `0 2px 8px rgba(0,0,0,0.4)` ＋ 上辺に `1px rgba(255,255,255,0.08)` のインナーハイライン |

**ピル形と 1px のインナーハイライトがボタンたることの正体**。暗い背景では、面を塗っただけの矩形はラベル付きの帯にしか見えない。上辺だけに薄く光る線を入れると、**光源が上にある立体**として読まれ、押せるものとして認識される。影は落としすぎない――2px / 8px で十分で、深い影はモーダル感が出て地図から浮いてしまう。

角丸が完全なピルにあるのは、この画面の他のどの要素とも形が被らないようにするため。カードは 16pt、シートは 24pt、ノードは正円。**丸みだけがボタンの形**という語彙を作る。

#### 4.6.2 種別

| 種別 | 用途 | 塗り | 文字 |
| --- | --- | --- | --- |
| **Primary** | 画面で最も進めたい 1 つ（もっと掘る・無料で始める） | `accent/primary` のべた | `#FFFFFF` |
| **Secondary** | 並列に置く選択肢（サービスで聴く） | `bg/elevated` ＋ 1px `#2A2A38` の境界 | `text/primary` |
| **Ghost** | 補助操作（ジャンル・組み込む・中心に戻る） | 透明 ＋ 1px 境界のみ | `text/secondary` |
| **Locked** | 課金が必要な操作 | `accent/primary` の 12% ティント ＋ 鍵アイコン | `accent/glow` |

**1 画面に Primary は 1 つだけ**。SC-05 では「段階表示ボタン」が Primary、ジャンル・組み込・中心に戻るの 3 つは Ghost、SC-06 では「もっと聴く」が Primary。この規約が守られていれば、ユーザーは迷わない。

#### 4.6.3 状態

| 状態 | 表現 |
| --- | --- |
| 通常 | 上記のとおり |
| 押下中 | **scale 0.96 ＋ 影を 0 に ＋ 明度 −8%**、100ms / ease-out |
| 押下解放 | scale 1.0 へ spring(stiffness 400, damping 22)、わずかに跳ねる |
| 無効 | 不透明度 0.35、影なし。タップ時は 60ms の横振動（±3pt）で拒否を示す |
| ローディング | ラベルを保持したまま右端にスピナー。**幅は変わらない**（レイアウトが動くと不快） |
| 触覚 | 通常押下は `impactLight`、Locked 押下は `notificationWarning` |

**押下中に影を消して縮める**の 2 点がこの設計の要点である。影を残したまま縮めると、小さくなっただけに見えやすい。影を消すと**沈み込む**ように見える。物理的に押しているという知覚は、この 2 つが同時に動くときにだけ生まれる。

#### 4.6.4 段階表示ボタンの 3 態

`StepRevealButton` は FR-28 の中核 UI であり、状態によって見た目と意味が変わる。

```
「通常・残りあり」                「上限・Free」              「上限・Pro」
┌──────────────────────┐      ┌──────────────────────┐   ┌────────────────────┐
│   ＋ さらに 10 件      │      │  🔒 もっとディグる     │   │   全 100 件を表示中 │
│      あと 20 件        │      │        ＋70           │   └────────────────────┘
└──────────────────────┘      └──────────────────────┘
  Primary（アクセント塗り）        Locked（ティント＋鍵）        無効（不透明度 0.35）
```

| 要素 | 仕様 |
| --- | --- |
| 主ラベル | 「＋ さらに 10 件」、Label L（16 / Semibold） |
| 副ラベル | 「あと N 件」、Caption 12 / `text/secondary`、主ラベルの下に 2pt |
| 進捗 | ボタン下端に 2px の進捗バー（表示済み / 上限）、`accent/glow` |
| 長押し | 権利範囲の全件を一度に開く。長押し中はバー伸びる予備アニメーション |
| Free 上限時 | **同じ位置のまま Locked 種別へ変化**。表記・色・アイコンを差し替える（450ms のクロスフェード） |
| Pro 上限時 | 無効状態。押しても何も起こらないが、消えずに残す（全件表示していることを伝える） |
| 押下回数 | **Free: 3 回で 30 件、Pro: 10 回で 100 件** |

**ボタンを移動させずに意味だけ変える**のがこの設計の芯である。3 回押して増える位置を覚えたユーザーが、同じ場所が課題ボタンに変わることに、迷路を別の場所に置かれる焦燥を持ち込まない――**押すたびに「あと N 件」が減っているので、壁が近づくことは事前に見えている**。

**v3.0 で数字が +120 から +70 に変わった**。Pro 側の押下回数が 15 回から 10 回に減っているが、**Pro のユーザーが全件に到達するまでの手数が短くなるのは良い変化**である――15 回は途中で長押しに切り替えたくなる回数だった。

### 4.7 ラベル配置

アーティスト名を読ませることは、v3.0 で **性能要件に格上げ**した（基本設計書 §10）。読む手段を外部アプリに渡した以上、**名前だけがユーザーの手がかりの中核**だからである。

#### 4.7.1 二段構えの方針

| 段 | やること | 効く場面 |
| --- | --- | --- |
| ① **レイアウト時に押し出す** | ノード間の最小距離を **ラベル幅を見込んだ値** で計算する | 地図全体の密度 |
| ② **描画時に衝突を避ける** | 8 方向の候補位置を試す。置けなければ消える | 局所的な密 |

**ラベルは画面座標で一定サイズに持つ**。ノードはズームと共に拡大されるが、文字は大きくならない。この非対称性が重要で、**拡大するほど相対的に空が広がり配置が易しくなる**――地図を拡大すると地名が出てくるのと同じ振る舞いになる。

#### 4.7.2 配置アルゴリズム

1. 優先順（選択中 → `rank` 昇順）に並べる
2. 各ノードにつき **8 方向の候補位置**（右・右上・上・左上・左・左下・下・右下）を、順に試す
3. 既に置いたラベルおよび **中心ノードの予約矩形** と衝突しなければ確定
4. ラベルが置けなければ **消える**

行 1.2 未満では関連しないもの外側ラベルが混む――全ノードが同格なので、一部だけ消すと基準が不明になる。

**「置けなければ消える」という割り切りが、この設計の中心である**。重なって無理に描くと、**重なった 2 つの名前のどちらも読めなくなる**――情報量は増えたつもりが、読めなければ実質的に少ない方は **拡大すれば必ず現れる**。

これが成立するのは、拡大という逃げ道が常にあるからである。**非機能要件の「倍率 3.0 まで拡大すれば全ノードの名前に到達できるはず」は、この割り切りと対になる保証**である。片方だけでは成立しない。

#### 4.7.3 ジェスチャ中の振る舞い

ピンチ・パンの途中では **再配置しない**。確定済みの配置に **差分変換（平行移動・スケール）だけを指の動きに追従させ、指が離れた時点で置き直す**。

| 局面 | 振る舞い |
| --- | --- |
| ジェスチャ中 | 差分変換で追従。**ラベルは消えない** |
| 指が離れた瞬間 | 新しい配置で再配置。150ms のクロスフェード |
| 「中心に戻る」 | **再配置の commit をカメラのアニメーション完了まで遅延させる**。イージングを `recenter` で揃える |
| 段階表示の追加 | 既存ラベルは動かさず、追加分だけ置く（レイアウト自体が変わった場合は全体再配置） |

**この 2 行目と 3 行目は実機フィードバック由来である**。当初は操作中にラベルを隠す実装だった。**拡大しようとした瞬間に名前が全部消えるのは、拡大の目的そのものを潰している**。同様に「中心に戻る」でカメラだけ先に動くとラベルが最終位置へ瞬時にワープしたのは、**地図と文字が別の物体に見えてしまう**。

**検索結果の見え方（v3.2）**

検索対象は全アーティストで、**類似度グラフを持つものと持たないものを混ぜる**（基本設計書FR-01）。

| 方針 | 内容 |
| --- | --- |
| **区別しない** | **バッジやセクション分けをしない**。並び順は `popularity` 降順で、グラフの有無では並べ替えない |
| 変わるのは選んだ後 | グラフがあれば関連アーティスト地図、なければジャンル地図（SC-05） |
| 重複 | **齟齬済みのアーティストは 1 行に統合して返す**。重複率は代表 500 クエリで 2% 未満に抑える（基本設計書R-40） |

**「この人は地図を掘れる」と事前に言わない**。検索結果に印をつけると、**ユーザーはその印を避けて選ぶようになる**――ロングテールアーティストを拾えるアプリでありながら警告を出すのは自己矛盾である。

選んだ後に出てくるのは、関連アーティスト地図ではなくジャンル地図であるが、これは **劣化版ではなく、別の軸の地図** である（FR-29）。島レイアウトが段階表示のまま効く、黙って最適な地図を出すほうが、事前に断られる体験より良い。

**`RandomToggle` を検索本文の直下に置くのは、これから引く地図の性質を決める操作だからである**。設定画面の奥ではなく、検索の直後――決める瞬間に見える場所に置く。

OFF が既定であることも重要で、**同じアーティストを検索すれば同じ地図が出る**のが v3.0 の標準的な振る舞いになる。ランダムは「そういう」ことを知った上で選ぶものであって、**選んだつもりが結果が変わることが最悪になる**（基本設計書FR-30）。

### 5.2 SC-05 マップ（中核画面）

**目的**: 地図を触ることそのものだけで探索が完結する。他の画面はすべて補助である。

**レイアウト**

```
┌───────────────────────────────┐
│ ‹  Radiohead                ⋮ │ ← 上部クローム（半透明バー）
│   確定 16 ・ 類似度順 14 ・ 10/30 │
├───────────────────────────────┤
│ [ 関連アーティスト | 同じジャンル ] │ ← ViewTypeSwitch（FR-29）
│                                 │
│            （地図）                │
│                                 │
│                                 │
├───────────────────────────────┤
│ ［ ＋ さらに 10 件    ▬▬▬ ］  │ ← StepRevealButton（FR-28）
│ [ジャンル 8] [ 組み込 ] [中心に戻る] │ ← Ghost 3 つ
└───────────────────────────────┘
```

**⋮ メニュー**: 🎲 引き直し（ランダム表示 ON のときだけ有効）／画像で共有

**v3.0 で上部ボタンが 4 つから 3 つになった**。「全体表示」を廃止し、**空白部分のダブルタップに移設した**。常設ボタンとしては使用頻度が低く、操作余の圧迫していたためである。

代わりに入ったのが**中心に戻る**（旧「全体表示」）である。全体を見渡すという目的より、**検索したアーティストを起点に戻す**方に絞った――迷って迷子になったときに欲しいのは、全体像ではなく、原点だからである。

**上部クローム**

| 要素 | 仕様 |
| --- | --- |
| 背景 | **`bg/chrome`（`rgba(18,18,26,0.94)`）＋上端に hairline，`shadow.panel`** |
| タイトル | シード名、Title 22 / Semibold |
| サブタイトル | 「確定 N ・ 類似度順 M ・表示/上限」（ランダム表示 ON のときは「・ ランダム M」） |
| ‹ | 戻る（履歴を 1 つ遡る） |
| ⋮ | オーバーレイメニュー |

**上部クロームを半透明バーにしたのは実機検証の結果である**。背景を透かすデザインだと、ノードやラベルが真下に来たときに **タイトルが地図に食われて読めなくなる**。地図は何がラベル近くに来るか制御できない以上、文字側を守る必要がある。

**ノードの描画**

| 層 | 配置 | 塗り |
| --- | --- | --- |
| 中心（シード） | 固定、大きさの倍率で | `accent/primary` ＋ `accent/glow` のグロー、**人アイコン** |
| 確定枠 | 中心寄り、類似度に応じた距離 | `tier/core`（高彩度） |
| 外側 | その続き、**同じ同心系に置く** | `tier/random`（一段落として） |
| ゴースト | 外周に散らし、数だけ示す | `state/locked` の輪郭のみ |

**サブジャンルの島レイアウト（`viewType = genre`）** では層を分けない、サブジャンルごとの島中心へ引き寄せ、島同士は反発する。塗りは一律 `tier/core`、エッジは中心からの放射線のみ。

**ノードの状態**

| 状態 | 表現 | 意味 |
| --- | --- | --- |
| 未聴 | 塗りなし、輪郭のみ | まだ何もされていない |
| **チェック済み** | **右上に白丸（チェック）**（`state/checked`） | **詳細シートを開いた（FR-31）** |
| 既聴 | 塗りつぶす | 外部アプリへ遷移した |
| 選択中 | 拡大 1.25、発光リング | 今シートが開いている |
| 組み込み対象 | **アクセント色で強く呼吸**（`breathe.marked`） | SC-16 で選ばれている |

**「見た」と「聴いた」を別の状態にしている**。チェック済みは詳細を開いたこと、既聴は外部アプリへ飛んだことを意味する。100 ノードを拡大・移動しながら見ていると **どれを見たか分からなくなる**――これはβ実装が触って初めて分かった問題で、仕様上の推論からは出てこなかった。**地図を歩く体験には、足跡が要る**

**エッジの表現**

| 関係タイプ | 線の表現 |
| --- | --- |
| 共聴 | 実線・低彩度 |
| 共演・メンバー | 二重線・アクセント色 |
| 影響 | 破線・矢印付き |
| 同レーベル | 点線 |

エッジはノード出現に合わせて **`edgeGrow`（420ms）で中心側から伸びる**。外側と島レイアウトには関係エッジを引かない――関連はいくらでも関連しうると主張できるほど強くないため、線を引くと嘘になる。

**「ルートが伸びる」アニメーションは、単なる装飾ではない**。ノードを一斉にフェードインさせるだけだと、**新しく出たノードがどこから来たのかが伝わらない**。中心側から線が伸びて反端にノードが現れることで、**関係の向きが動きで読める**。

**インタラクション**

| 操作 | 対象 | 意味 |
| --- | --- | --- |
| **バンド** | **キャンバス** | **拡大縮小。倍率 0.5〜3.0。ラベルは追従して消えない（§4.7.3）** |
| ドラッグ | キャンバス | バンド後スクロールする |
| タップ | ノード | SC-06 を peek で開く**同時にチェック済みになる** |
| ダブルタップ | ノード | 同じディグ（このノードを新シードに） |
| 長押し | ノード | SC-06 を開く**チェック済みにならない**（下見用） |
| タップ | ゴースト | SC-09 ペイウォールを開く |
| **ダブルタップ** | **空白領域** | **全体表示にリセット** |
| タップ | `StepRevealButton` | 次の 10 件を追加表示（FR-28） |
| 長押し | `StepRevealButton` | 権利範囲の全件を一度に開く |
| タップ | `ViewTypeSwitch` | 表示タイプを切り替える（FR-29）。**往復しても結果は保持される** |
| タップ | （ジャンル N） | SC-07 を展開。**N は表示中ノードのジャンル数** |
| タップ | （組み込） | SC-16 を開く。Free は鍵バッジ付きで SC-09 へ |
| タップ | （中心に戻る） | シードを中心に戻す。**ラベルもカメラと一緒に動く** |
| タップ | ⋮ | 引き直し（FR-27）。画像で共有 |

**段階表示の演出（FR-28）**

1. 追加された 10 件のエッジが中心側から伸びる（`edgeGrow` 420ms）
2. 反端にノードが stagger 20ms で出現する（`reveal` 220ms）
3. **カメラは動かさない**。見ている場所が唐突に変わるのを防ぐ
4. 新しいノードが画面外に出る場合、自動では追わない。「中心に戻る」を使えばよい

**空状態・縮退**

| 状態 | 表示 |
| --- | --- |
| **グラフを持たないアーティスト** | **無言でジャンル地図に切り替わる**（基本設計書FR-01）。上部の表示タイプ切替は「同じジャンル」が選択済みの状態で開き、関連アーティスト側は無効化してロックアイコンで理由を示す |
| 関連が 5 件未満 | 地図は描けるが「このアーティストは情報が少ないです」と SC-07 への導線 |
| プール枯渇 | ⋮ の引き直しを無効化し、理由をロックアイコンで示す |
| 通信断 | 直近のキャッシュをローカルから復元、SC-15 を重ねる |

### 5.3 SC-06 アーティスト詳細（ボトムシート）

**目的**: あなたのアーティストが出てきたのかを読ませ、**聴きたくなったら 1 タップで選ばれる**。


**シートを開いただけでチェック済みになる（FR-31）**。ノードをタップしてシートを開いた時点で印を付けるので、ユーザーは何も操作しなくてもいい。

ただ **長押しで開いた場合は付けない**。ちょっと見て戻すことを見に区別される場面があるためで、**ユーザーが自分で足跡を残すか選べる**ようになっている。

### 5.7 SC-11 マイディグ

上部にセグメントコントロール（「履歴」「保存」）、**すべて端末 DB から読むので、オフラインで完全に機能する**（基本設計書 §7.4）。

| タブ | 内容 |
| --- | --- |
| 履歴 | 生成したマップを日付降順で表示。各行にシード名・表示タイプのアイコン・ノード数・日時。**引き直しは別行として並び、親からの系譜を細字で示す** |
| 保存 | ブックマークしたアーティスト・ジャンル・マップをタブで分類 |

**v3.1 で追加した操作**（いずれも端末 DB への SQL 一発で書く）

| 操作 | 挙動 |
| --- | --- |
| **検索** | リスト上部の検索欄。**シード名だけでなく含まれるアーティスト名でも引ける**（`map_nodes` を引く） |
| **並べ替え** | 日付降順（既定）／最近開いた順／ノード数順 |
| **組み込み** | 表示タイプ（関連／同じジャンル）・ランダム表示の ON/OFF |

持っていると **「あの名前を前にどこで見えた」という瞬間を思い出せる**。そのときにどの地図で見えたか引けることは、探索の連続性を保つ上で想像より大きく、チェック済み（FR-31）と合わせて **セッションをまたいだ足跡を残す**。

v2.2 にあった「共有中」タブは v2.4 で変わり、リリース後に地図共有を実装する際は**このセグメントに 3 つ目を追加するだけ**で済む形にしてある。

### 5.9 SC-15 エラー／オフライン

| 状況 | 表示 | 復帰手段 |
| --- | --- | --- |
| **ネットワーク断（履歴・ブックマーク）** | **バナー出さない。端末 DB から読むので完全に動く**（FR-19） | ─ |
| **ネットワーク断（新規検索）** | **端末 DB の FTS で「過去に見たアーティストだけ」を返し、「オフラインのため見たことのあるアーティストだけ探しています」と添える** | 自動再接続 |
| **ネットワーク断（未取得の地図生成）** | 画面上部にスリムなバナー「オフラインです」（履歴への導線 | 自動再接続 |
| **オフライン中の操作** | **ブックマーク・チェックはその場で反映する**。同期待ちであることは UI に出さない | 復帰時に自動送信 |
| API 障害 | グラフ領域に EmptyState。「いま地図を描けませんでした」再試行 | 再試行、または別シード |
| 外部リンクの ID なし | **UI 上は何も変わらない。名称検索 URL を開く**（FR-23） | ─ |
| 検索 0 件 | 「該当するアーティストが見つかりません」表記からの提案 | 別語の修正 |
| 関連 0 件 | 「このアーティストの関連データはまだ少ないです」ジャンル起点タグへの導線 | ジャンルから掘る |
| 外部アプリ未インストール | OS がブラウザまたはストアへフォールバック | 設定で別のサービスを選ぶ |
| レート制限（429） | 「少し混み合っています」残り秒数 | 自動リトライ |
| 課金失敗 | ストア標準のエラーを踏襲、アプリ側は復元導線のみ提示 | 購入を復元 |
| **端末 DB の破損** | **起動時に検知し、黙って作り直す**。同期済みのユーザーデータはサーバーから戻る | 自動 |

**v3.1 でオフラインの意味が変わった**。v3.0 までは、通信がないと何もできないアプリが、直近分だけ見えているという状態だったが、v3.1 では **履歴にある 60 件はすべてオンラインと全く同じように開く**。

ただ **一行目では「地図が出せない」**。できないことなのに、オフラインであると伝わるのは、**機能が制限されているという誤った印象を与えるだけ**だからである。バナーを出すのは、**実際にできないこと（新しい地図の生成）が起きたときだけ**とする。

**「データの欠落」をエラーとして見せない**の v3.0 から一貫した方針である。外部リンクの ID は人気アーティストほど揃いやすいほど欠けやすい、**まさにディグの価値が高い領域で情報がありませんと出すのは最悪**なので、黙って名称検索 URL に迂回する。端末 DB の破損も黙って作り直すのが同じ考え方である。

### 5.10 SC-16 フィルタパネル

自動データ保持により実現可能になった組み込み機能（FR-22）が、**v3.0 で 3 軸に絞った**。

| 軸 | UI | 備考 |
| --- | --- | --- |
| **年代** | 両端スライダー | 活動開始年の範囲 |
| **関係タイプ** | 4 種のチップ | 共聴・共演・メンバー、影響、同レーベル。**それぞれの色は `relationStyle.chip`** を使う（§4.1） |
| **国** | 主要国のチップ | 表示中のノードに存在する国だけを並べる |

**適用中の表現**

- 対象のノードは **アクセント色で強く呼吸**（`breathe.marked` = 380ms）
- 対象外は **削除せずに沈む**（不透明度 0.1）。地図の形が崩れないようにする
- 適用は `filters.on` で明示的に切り替え、判定は `isExcluded` に一本化
- フィルタは Pro 限定。Free ではボタンに鍵がつき、適用時に SC-09 を明示する

**v3.0 で「層を検索（確定枠のみ・ランダム枠のみ）」を廃止した**。二層構造は **地図の見た目（塗りの明度差）ですでに表現されている**ので、フィルタに含めると概念が二重になり、同じことを 2 つの場所で説明するのは、丁寧ではなく冗長である。

「試聴可能のみ」（レビュー廃止（基本設計書 §3.1.2）に伴って消えた結果として、フィルタは **5 軸から 3 軸** になり、ちょうど 1 画面に収まるようになった。

### 5.11 SC-14 画像共有

**目的**: 自分の地図を 1 枚の画像にして SNS に貼れるようにする（FR-17）。

```
┌───────────────────────────────┐
│         ▬▬▬                 │
│  画像で共有                  │
│                             │
│  ┌─────────────────────────┐  │
│  │    ●  ●    ●          │  │  ← 生成画像のプレビュー
│  │  ●  (📤)  ●        │  │
│  │    ●  ●    ●          │  │
│  │  Radiohead から        │  │
│  │  DIGGR                │  │
│  └─────────────────────────┘  │
│                             │
│  ( 正方形 ) ( 縦長 )        │  ← アスペクト比
│  ─ アーティスト名を隠す     │
│                             │
│  ┌─────────────────────────┐  │
│  │  🖼 画像を共有          │  │  ← Primary
│  └─────────────────────────┘  │
│  💾 画像を保存                │  ← Ghost
└───────────────────────────────┘
```

| 要素 | 挙動 |
| --- | --- |
| 画像の内容 | 現在のグラフのレンダリングそのもの（シード名・段階表示分のアーティスト名） |
| アスペクト比 | 正方形（1:1）と縦長（9:16）の 2 種。SNS の主要な位置に合わせる |
| アーティスト名 | 既定 OFF、ON にすると確定枠の名前だけ、隠しても地図の形は保つ |
| 生成 | クライアント側で Skia のオフスクリーン描画。**サーバー通信なし** |
| 共有 | OS の共有シートに PNG を渡す |
| 保存 | 写真ライブラリへ保存（権限は初回のみ確認） |

**リンク共有と違って、画像共有はサーバー側の仕組みを作る必要としない**。データの永続化や受け取り側の権限判定を Universal Link が不要で、クライアントで描画して共有シートに渡すだけである。だから v1.0 に残せた。

ただし **画像は見て終わり**である。開いた先がアプリに繋がっていない。新規ユーザー獲得を頼っておらず、リリース後の地図共有（基本設計書 §11.2）が本当であるが、画像共有はその手段の次善策と位置づける。

## 6. 状態一覧

各画面が取りうる状態を実装前に確定させる。UI コンポーネントは以下 5 状態すべてを同時に実装する。`ArtistNode` はさらに加えて未聴・チェック済み・既聴・選択中・組み込み対象の 5 状態を持つ（§5.2）。

| 状態 | 定義 |
| --- | --- |
| Loading | 初回取得中。スケルトンまたは部分描画で表現。全画面スピナーは使わない |
| Empty | データ 0 件。次の行動を促す文言と CTA を必ず添える |
| Error | 取得失敗。原因の簡潔な説明と再試行手段を提示する |
| Locked | 権利不足による制限。ボーダー表現と解放導線を提示する |
| Ready | 通常表示 |

## 7. アクセシビリティ

- 全ノードに `accessibilityLabel`（アーティスト名・類似度 94 パーセント・閲覧済み）を付与、VoiceOver / TalkBack で順に読み上げ可能にする。**ラベルを RN の `<Text>` で持っているためそのまま読み上げ対象として自然に乗る**（§4.5）
- グラフ操作の代替として、詳細シートに「関連アーティスト一覧」のリスト表示を用意する（スクリーンリーダー利用時は既定でリスト表示に切り替え）
- 「アニメーションを減らす」設定および OS の Reduce Motion に従い、**呼吸・ルート伸長・stagger をすべて停止する**（§4.4）
- **バンド操作の代替手段を用意する**。OS のズーム機能に頼らず、詳細シートのリスト表示から同じ情報に到達できるようにする
- ジャンル色のみで情報を区別しない、必ずラベルを併記する（色覚特性への配慮）
- 全テキストのコントラスト比 4.5:1 以上、タップ領域 44×44pt 以上を維持する
