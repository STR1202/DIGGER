## 最悪のシナリオは「DB 全滅」ではなく「DB 全滅＋パイプライン実行中」

`music_v{n}` は月次パイプラインが再構築できるので、それ自体はバックアップ不要。
本当に困るのは **ユーザーデータ（public スキーマ）** を失うケースで、これは
毎日 `backup.sh` を取っている前提で最大 24 時間分の損失に抑える。

## 手順（ダウンロード → 復元 → 起動 → 確認）

```bash
# 1. 直近のバックアップを取得（同一 VPS 上、または退避先ストレージから）
ls -lt /var/backups/diggr/*.dump | head -1

# 2. 空の PostgreSQL に復元
cd /opt/diggr/infra
docker compose up -d postgres
./restore.sh /var/backups/diggr/<file>.dump

# 3. API を起動して疎通確認
docker compose up -d api
curl -f http://localhost:8080/health
curl -f http://localhost:8080/v1/me/maps -H "Authorization: Bearer <token>"
```

## `music_v{n}` を持たない状態で API が動くことの確認

`MockRepository` にフォールバックしない限り、`music_v{n}` が無いと検索・マップ生成は
404 やエラーになるが、**認証・ユーザーデータ系（/me/*）は影響を受けない**。
復旧直後にまずここが動くことを確認すれば、「サービス全断」ではなく
「中核機能の一部不通」に留められる。
